## Objective

Give the owner ten rolling seasons of nflverse weekly (game-by-game) player stats, plus team defense and special teams (D/ST) rows, in a finished Excel workbook with fantasy points for each of the owner's leagues. A Python pipeline (standard library only) downloads the nflverse files, derives long-touchdown counts from play-by-play, builds one D/ST row per team-game, scores every league in the config files, runs data gates and publishes plain CSV files only when every blocking gate passes. Since 2026-11-20 everything lives in the public repository wes-blue/sports-analysis, in the NFL/ folder of a layout built for more than one sport, and GitHub is the only runtime: GitHub Actions runs the pipeline on a schedule and whenever the owner saves a change to a scoring file on GitHub, and commits the published files. From version 3.001 the pipeline also builds the workbook itself after every publish (python -m nflpipe export): a values-only file with no Power Query, formulas or refresh, uploaded as a release asset at a stable download link and not committed to git (D-041, D-042). The owner downloads it and opens it with Excel only: no Python, no git and no copy of the repository. Scoring is changed by editing NFL/02-config on GitHub, which rebuilds the workbook. The earlier Power Query workbook (2.x) is retired (D-043). Every increment is a numbered version, and every requirement, risk and control traces to an owner instruction, a decision, a contract section or a verified finding.

## Scope

### In scope

- A Python pipeline (standard library only at run time) that combines nflverse weekly player stats for a rolling 10-season window (Latest-9 to Latest by default, REG+POST, configurable).
- Derived metrics: long-TD counts from play-by-play for every season in the window, and one team D/ST row per team-game, including ESPN's points-allowed rule.
- Scoring of every league in NFL/02-config: linear weights, bonus bands and the Applies_To position gate, including the control leagues Standard and PPR and the owner's ESPN_League.
- Data gates that stop a bad run from publishing, and published CSV files with provenance (sources, manifest, status, run log, check files, config copies).
- GitHub Actions workflows installed at /.github/workflows/ (weekly in season and on a config change, monthly full run with heartbeat, Friday watchdog, tests), with alerts as rolling issues and an owner's guide (NFL/03-pipeline/AUTOMATION.md).
- A finished, values-only Excel workbook built by the pipeline on GitHub after every publish (python -m nflpipe export), published as a release asset at a stable download link and not committed to git (D-041, D-042; CONTRACTS.md section 13).
- The data dictionary, the published check results and the rules used for the scores, inside the workbook (Dictionary, Checks, Leagues, Scoring and Bonus sheets), generated from the published data.
- Duties of a public repository: the nflverse CC BY 4.0 attribution (DATA-LICENSE.md), a personal-data check before anything is published, and a layout and template that let another sport be added.
- A BLOCKERS.csv process for every question or action that needs the owner, with a stated default used meanwhile.
- Later increments: automation proven on GitHub, the remaining ESPN rules, an analysis layer on the workbook, platform preset leagues, hardening and a user guide.

### Out of scope

- R; and Python, git or a copy of the repository on the owner's computer as a requirement for anything routine (a developer may still run the pipeline by hand).
- nflverse datasets beyond the four named sources (for example Next Gen Stats, snap counts, injuries).
- Live connections to ESPN, Sleeper, Yahoo, DraftKings or FanDuel league APIs; league settings are entered by hand.
- Projections, rankings advice or draft tools.
- Sports other than NFL for now; the structure and _Sport-Template/ allow them later (D-033).
- Publishing the private 1.x archive, the transcript, the raw ESPN pastes or the prior-art reviews (D-034; BLOCKERS.csv Q-018).
- A second data repository, tokens or secrets in the workflows (removed by D-036).
- GitHub Actions artifacts as the data or workbook channel, and an external scheduler service.
- Individual defensive player (IDP) scoring work beyond the existing harmless weights (D-017).
- Merges to main by Claude, unless the owner says so in chat (CLAUDE.md §6).
- Power Query, formulas, connections, macros or a Data Model in the workbook, and a refresh in Excel (retired, D-041, D-043); the 2.x sources are archived and not maintained.
- Scoring changes inside the downloaded workbook: rules are changed in NFL/02-config on GitHub (D-041).
- Committing the generated workbook to git (D-042).

## Glossary

| Term | Definition |
|---|---|
| nflverse | Open-source NFL data project on GitHub that publishes player, team, schedule and play-by-play data as downloadable files. |
| stats_player release | The nflverse download area holding stats_player_week_<season>.csv, one row per player per game. |
| Play-by-play | nflverse's file with one row per play; the only exact source of how long a touchdown was. |
| Long TD | A touchdown of 40 or more yards. Counts are cumulative: a 55-yard TD counts in both the 40+ and the 50+ column. |
| D/ST row | One row per team per game (player_id DST_<TEAM>, position DST) holding team defense and special teams stats, so it can be scored like a player. |
| season_type | REG (regular season) or POST (playoffs). |
| fantasy_points / fantasy_points_ppr | nflverse's own Standard and Full-PPR points per row, used as accuracy controls. |
| PPR | Points per reception: 0 (Standard), 0.5 (Half) or 1 (Full) point per catch. |
| League | One fantasy league's scoring rules: a weight column in the scoring table plus a row in the league list. Not an NFL league. |
| Control league | A league (Standard or PPR) whose points must equal an nflverse column, proving the scoring engine is right. |
| Bonus band | A rule that awards points when a stat falls between a lower and an upper limit, for example +1 for 300-399 passing yards. |
| Position gate (Applies_To) | A column saying which positions a rule applies to; blank means everyone. |
| Golden sample | A small set of player-games whose expected points were checked by hand, used to catch regressions. |
| Python | A programming language. Here it runs the pipeline on GitHub's computers; you do not need it on your computer. |
| Standard library | The parts of Python that come with every installation, so the pipeline needs nothing extra installed. |
| Pipeline | The Python program (nflpipe) that downloads, derives, scores, checks and publishes the data, in that order. |
| Command and exit code | The pipeline is started with a typed command such as 'python -m nflpipe run' (on GitHub, by a workflow). When it ends it returns a number: 0 published, 3 nothing to do, 4 held by a failed gate, 5 stale, 1 error. |
| PUBLISH / SKIP / HOLD | The three normal outcomes of a run: new files written; nothing changed upstream so nothing written; a blocking gate failed so nothing written. |
| Gate | An automatic check the pipeline runs before publishing. A blocking gate stops the publish when it fails; an advisory gate only warns. |
| CSV | A plain text table, one row per line, columns separated by commas; Excel opens it directly, and the pipeline's exporter turns the published CSV files into the workbook. |
| Published data (04-data) | The CSV files the pipeline writes to NFL/04-data for the exporter and anyone else to read. Never edited by hand. |
| Data contract version | A whole number in status.csv that changes only when a published file's columns or meaning change; the workbook checks it. |
| Pipeline version | The pipeline's own version (for example 1.1.0) in status.csv; the middle number rises when scoring arithmetic or a derived-metric rule changes. It is separate from the workbook's version. |
| Manifest | manifest.csv: the list of published files with their row counts and fingerprints, used to prove nothing was altered. |
| SHA-256 (hash) | A fingerprint of a file's exact bytes; if one byte changes, the fingerprint changes. |
| Last-Modified | The time a web server says a file last changed; the pipeline uses it to know whether nflverse updated a file. |
| Back-correction (restatement) | nflverse changing a value in a game that was already published, sometimes months later. |
| Idempotent | Running the same thing twice gives the same result as running it once; a repeat run changes nothing. |
| GitHub | The website that stores this project's files and their full history. |
| Repository (private or public) | A project's folder on GitHub with its history. A private one needs a sign-in to read; a public one, like wes-blue/sports-analysis, can be read by anyone, including Excel, without a sign-in. |
| Clone and sync | A copy of the repository on a computer, kept up to date with GitHub Desktop or 'git pull'. Not needed to use the workbook. |
| Commit | A saved, dated change to the repository's files, with a message saying what changed. |
| Branch, default branch and pull request | A branch is a separate line of changes; the default branch (main) is the official one; a pull request asks to merge a branch into it. |
| GitHub Actions | GitHub's service that runs programs on GitHub's computers when something happens or on a schedule. |
| Workflow | A file that tells GitHub Actions what to run and when. It works only from the .github/workflows folder at the top of the repository, and its schedule only on the default branch. The NFL workflows are named nfl-pipeline-*.yml. |
| Schedule (cron) | The timing line in a workflow, for example 'Tuesday, Wednesday and Thursday at 17 minutes past the hour'. GitHub often starts scheduled runs late. |
| Manual dispatch | Starting a workflow by hand from GitHub's Actions page instead of waiting for its schedule. |
| Watchdog | A separate workflow that turns red if no new data was published recently, so a silent failure gets noticed. |
| Rolling issue | One GitHub issue (a tracked to-do item) that the workflow opens on a failure and updates on later failures, instead of opening many. |
| pytest and CI | pytest runs the automated tests; CI (continuous integration) is a workflow that runs them on every change. |
| Token and secret | A password-like key that lets a workflow write somewhere; a secret is GitHub's safe store for it. The NFL workflows use none: they rely on the permission GitHub gives each run. |
| DataLocation | A setting of the retired 2.x Power Query workbook (tblConfig) that told it where to read the published CSVs. The 3.x workbook has no such setting (D-041). |
| Parity check | A check of the retired 2.x workbook that compared its own scores with the pipeline's. The 3.x workbook holds the pipeline's scores, so there is nothing to compare; control C-21 checks the copy. |
| Rules drift check | A check of the retired 2.x workbook that listed differences between its own scoring tables and the rules the pipeline used. The 3.x workbook shows the pipeline's rules as copies (control C-22). |
| tblConfig / tblLeagues / tblScoring / tblBonus / tblGolden | Tables of the retired 2.x workbook. The 3.x workbook keeps tblLeagues, tblScoring and tblBonus as read-only copies of the config files, plus tblPlayerGames, tblSeasonTotals, tblGates and tblDictionary (CONTRACTS.md section 13.2). |
| Data Model | Excel's in-memory store (Power Pivot), where the retired 2.x workbook loaded its scored table. The 3.x workbook does not use it. |
| Formula.Firewall | A Power Query error raised when one query mixes data sources in a way its privacy rules do not allow. It applied to the retired 2.x workbook; the 3.x workbook has no queries. |
| Schema drift | Changes to a data source's column names or layout over time. |
| BLOCKERS.csv | The file at the top of the repository listing questions and actions waiting on you, each with an ID (Q-001, ...), the default used meanwhile, an Answer column you fill in, a Status and Claude's response. |
| Transcript | The web-search conversation that started the project. It is kept in the owner's private repository (D-034); references such as 'Transcript L3' give its line numbers. |
| Data address | The public web address of a published file: https://raw.githubusercontent.com/wes-blue/sports-analysis/main/NFL/04-data/<path>. It serves the files on the main branch, with no sign-in. |
| raw.githubusercontent.com | GitHub's server for the plain contents of files in public repositories; the data address uses it. |
| Sport folder | A top-level folder of the repository holding one sport's project (NFL/ today), with the same numbered subfolders for every sport. _Sport-Template/ is the empty skeleton for the next one. |
| Design generation (major version) | The first digit of a workbook version. For NFL: 1.x was computed inside Excel plus the transitional 1.006, all in the private repository; 2.x was fed by the pipeline in this repository and computed in Power Query (retired); 3.x is the workbook the pipeline builds on GitHub (D-035, D-041). |
| Push trigger | A workflow that starts when a commit reaches a branch. The weekly NFL workflow starts on a push to main that changes NFL/02-config, so a scoring change saved on GitHub is published. |
| Heartbeat | Activity the monthly workflow creates so that GitHub does not disable the scheduled workflows after 60 days without repository activity. |
| Points allowed (ESPN rule) | dst_points_allowed_excl_def: the opponent's final score minus 6 for each touchdown the opponent's defense scored (an interception or fumble return). Special-teams return touchdowns still count. dst_points_allowed is the opponent's full final score. |
| CC BY 4.0 | The Creative Commons Attribution 4.0 International licence, which nflverse uses for its data. Anyone may share and adapt the data if they credit the source, link to the licence and say what they changed. |
| MIT licence | The licence of this repository's code and documents (LICENSE): anyone may reuse them if the copyright and licence notice are kept. It does not cover nflverse's data. |
| Attribution | The credit line a licence requires, here naming nflverse and linking to its data and to CC BY 4.0 (DATA-LICENSE.md). |
| Experimental workbook | A 2.x copy of the workbook with the queries already installed by editing its Power Query package. Never a release; archived in NFL/05-excel/archive-2.x and not maintained (D-043). |
| Exporter (nflpipe export) | The pipeline command that writes the workbook from the published files in NFL/04-data, using only the Python standard library (CONTRACTS.md section 13.1). |
| Values-only workbook | An Excel file that holds numbers and text only: no Power Query, formulas, connections or macros, so there is nothing to refresh and no prompt on opening. |
| Release asset | A file attached to a GitHub Release. The workbook is the asset NFL-Analysis.xlsx of the release tagged nfl-workbook, replaced on every publish and not stored in git (D-042). |
| Stable download link | https://github.com/wes-blue/sports-analysis/releases/download/nfl-workbook/NFL-Analysis.xlsx: always the newest workbook. |
| Workbook design version and data version | The design version (3.001) says how the workbook is built and changes only when its design changes; the data version (run id and data through, on the About sheet) changes with every publish (VERSIONING.md). |
| Archive (archive-2.x) | NFL/05-excel/archive-2.x: the retired Power Query workbook, its queries and generators. Not maintained (D-043). |
